Init App Token Replacement Gaps

Initializing a new app via scripts/init_app.sh can leave template tokens behind, which creates inconsistent branding and generated docs titles in downstream app repos.

Statusactive
Backportedno
Template referenceN/A
Last updated2026-03-09

Problem

After running app initialization with card values, several files still contained app-template or Template App strings. This required manual cleanup in files like README.md and scripts/generate_docs_pages.py.

Reusable Pattern

Add a post-init verification step that scans for known template tokens and fails if any are still present. Keep the list focused on intended replacements and allowlist expected template-only files.

Proposed Template Change

  • Update scripts/init_app.sh replacement logic to robustly handle header/title token updates.
  • Add a post-init assertion pass for known template tokens in app-facing files.
  • Document expected replacements and optional manual follow-up in README bootstrap docs.

Risk and Rollout Notes

  • Stricter token checks may flag existing repos with historical template wording.
  • Introduce checks in warning mode first, then enforce once false positives are resolved.
  • Keep a small allowlist for intentional references to the canonical template project.

Backport Status

Pending backport to the canonical template repository. When completed, set backported: true and populate templateRef in docs/learnings/catalog.json.
