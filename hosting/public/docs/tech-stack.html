Card app – Tech stack

First-pass overview of the tech stack for the card app. For site-wide infrastructure, directory structure, and deployment, see the haderach tech stack (docs/haderach/tech-stack.html in the repo).

Overview

The card app is a single-page application (SPA) for the card editor experience. It is one of the haderach apps and is served at haderach.ai/card/. It is built as a static bundle and deployed via Firebase Hosting; there is no card-specific backend.

Tech stack (card-specific)

  • Frontend: React, TypeScript.
  • Build: Vite. Config: base: '/card/', outDir: 'dist/card'. Output is copied to hosting/public/card/ by scripts/build_card.sh or by CI.

App structure

Under the repository root:

  • index.html – Vite entry; root for the SPA.
  • src/main.tsx – React entry.
  • src/App.tsx, src/CardCanvas.tsx, src/ControlsPanel.tsx – Main UI.
  • src/constants.ts, src/types.ts – Shared types and config.
  • public/ – Static assets (e.g. _redirects for some hosts).
  • vite.config.ts, tsconfig.json – Build configuration.

Build and run

  • Build: From repo root, npm run build produces dist/card/. For deployment, run ./scripts/build_card.sh so output is copied to hosting/public/card/.
  • Dev: npm run dev from repo root; dev server uses base: '/card/' so routes match production.

Documentation

Card docs are served at haderach.ai/card/docs/. Source lives in docs/; scripts/sync_docs.sh mirrors docs into hosting/public/docs/ for hosting output.

Dependencies on haderach

Hosting, rewrites, and deployment are described in the haderach tech stack doc. The card app only supplies the built files under hosting/public/card/; it does not define Firebase or CI config.
