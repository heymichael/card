Card Docs Shell UX Refresh

Requirements for improving readability and navigation consistency across /card/docs tabs.

1. Objective

Improve the user experience of card documentation surfaces by keeping navigation context stable, reducing visual inconsistency across tabs, and minimizing iframe-style rendering artifacts.

2. Scope

In Scope

  • Card docs shell behavior at /card/docs.
  • Tab interactions for Requirements, Priorities, and Testing detail pages.
  • Document typography/spacing consistency across shell-rendered content.

Out of Scope

  • Changes to card editor functionality at /card.
  • Workflow trigger policy changes (PR/deploy schedule semantics).
  • Cloud Run/IAP hardening architecture for docs delivery.

3. Functional Requirements

IDRequirementPriority
FR-UX-01 The header region (title, signed-in identity, and tab controls) shall remain visible while content scrolls independently. Must
FR-UX-02 The Requirements detail view (?tab=requirements&project=<slug>) shall render inline in the docs shell instead of using iframe presentation. Must
FR-UX-03 The Priorities tab content shall render inline in the docs shell with title text normalized to "To Do List". Must
FR-UX-04 The Testing detail documents (including Test Lineup and Testing Infrastructure) shall render inline in the docs shell. Must
FR-UX-05 Back navigation from inline detail views shall restore list view cleanly without stale content rendering beneath lists. Must
FR-UX-06 Test Lineup heading text shall be normalized to "Test Lineup" (remove card-app naming suffix). Should
FR-UX-07 Test Lineup metadata lines (Selection/Trigger/Environment/Platforms) should use tighter vertical spacing than regular paragraph copy for readability. Should

4. Non-Functional Requirements

IDRequirementPriority
NFR-UX-01 Typography and spacing should be visually consistent across shell-rendered docs content (headings, paragraphs, lists, code snippets). Must
NFR-UX-02 Rendering must be robust to rapid tab switching; stale async content loads must not overwrite the current active tab view. Must
NFR-UX-03 Fallback behavior for missing content should remain clear and non-breaking (display tab fallback text). Must

5. Acceptance Criteria

IDScenarioExpected Outcome
AC-UX-01 User scrolls within any docs tab list/detail. Header and tabs remain fixed; only content pane scrolls.
AC-UX-02 User opens a Requirements project then clicks Back. Requirements list is restored without residual project content below it.
AC-UX-03 User opens Priorities tab. Content is inline-rendered with heading "To Do List" and shell-consistent typography.
AC-UX-04 User opens Testing -> Test Lineup. Content is inline-rendered; heading reads "Test Lineup"; metadata lines are tightly spaced.
AC-UX-05 User rapidly switches between tabs during doc loads. Current tab view remains correct; stale content from previous tab does not appear.
